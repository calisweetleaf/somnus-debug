# Recipe: index one Python file with `structure`

**Tier:** supported now, with one known crash. **Tool:** `structure`.

Get a Markdown map of a file's classes, methods and module functions with line spans, without importing or running it.

## When to use

This section says what the index is good for.

Use it before editing an unfamiliar or dense file: it tells you where each definition starts and ends, its decorators and the first line of its docstring. It does not tell you what the code does, and it covers one file at a time.

## Steps

This section gives the commands. `sd` is `/tmp/w4/venv/bin/python -m somnus_debug.cli`.

```console
sd structure ../proj/pkg/b.py > b_index.md                                  # full index to a file (stdout by default)
sd structure ../proj/pkg/b.py --no-line-numbers --no-module-functions       # classes only, no spans
sd structure path/to/file.py -o index.md                                    # or write directly; --update-doc PATH regenerates an existing index
```

`structure` writes nothing unless you pass `-o` or `--update-doc` [VERIFIED by the fieldkit selftest, [stage 6 log](../_repro/logs/stage6_integrations.log)].

The failure case, on any file that carries a `# somnus:metadata:v2` header (every file in this repo):

```text
$ cp src/somnus_debug/__init__.py stamped.py && sd structure stamped.py
error: invalid syntax (stamped.py, line 9)                                   [exit=2]
$ sed -n 9p stamped.py
#     type: "source-code"
```

`structure` parses with `ast.parse(..., type_comments=True)` (`src/somnus_debug/structure/core.py:210`), and a comment line beginning `type:` is read as a type comment. The fix exists only in the repo-root duplicate `analyze_python_structure.py`; `src/`, the installed package and PyPI 0.1.0 all crash ([D-01](../../DISCOVERY-LEDGER.md#d-01)) [VERIFIED]. Workaround: [programmatic/index-stamped-file](../programmatic/index-stamped-file.md).

## Pitfalls

This section lists what trips people up.

- The flag is `--no-line-numbers`, not `--no-lines`; argparse rejects it with `unrecognized arguments: --no-lines` [VERIFIED in this wave, pre-reset exploratory run; argparse usage errors exit 2 per [lane-d exit codes](../../_evidence/agent-findings/lane-d-cli-tests/exit-codes.md)].
- Exit 2 means both "bad arguments" and "could not parse the file" ([D-18](../../DISCOVERY-LEDGER.md#d-18)); read stderr.
- A class nested in a class inside a function is rendered twice and counted twice ([D-24](../../DISCOVERY-LEDGER.md#d-24)).
- The header line says "Generated by `analyze_python_structure.py`" even when the package's `structure` produced it [VERIFIED, output above].
- To print just the lines of named definitions, see [advanced/findings-to-source-slices](../advanced/findings-to-source-slices.md).
