# Input and output contracts

This page specifies what each tool reads and what it emits: stdout lines, report formats, file locations, and the JSON schemas automation depends on. Doctor's JSON report shape was taken from a real report generated on a /tmp fixture in this wave, not from the source alone.

## Inputs

This section lists every input each tool consumes, including the implicit ones.

| Tool | Explicit inputs | Implicit inputs |
|---|---|---|
| doctor scan | `project_root`, `-c` config (YAML subset or JSON) | **cwd** (log location; relative paths); the running interpreter's `sys.path` and installed packages (third-party and missing-import resolution via `importlib.util.find_spec`); `sys.stdlib_module_names`; prior state in `<root>/.python_doctor/` |
| doctor history / rollback | `project_root`, `-c`, `--limit` / `--run-id` | the state DB |
| structure | one source file (UTF-8) | none |
| pycache-clean | `--config` YAML (needs PyYAML) | cwd (default config path; relative `roots`) |
| init-test-harness | `target` | the package's template files (`importlib.resources`) |
| run_test.py | none on argv | `PROJECT_ROOT`, `SINGLE_TEST_OUTPUT_DIR`; whatever `execute_test` reads |
| delta.py | two doctor JSON reports, optional dispositions JSON | the filesystem under `--root`, used to tell dropped files from deleted ones |

## doctor JSON report (schema as observed)

This section gives the real key structure of `production_doctor_report.json`. It is the contract consumed by `delta.py`, the fieldkit recipes, and any CI parser.

Generated by `somnus-debug doctor scan . --no-state` in `/tmp/w2/qs/myproj`: three files (`app/__init__.py`, `app/core.py`, `tests/test_core.py`), exit 1. The shape below was dumped by walking the parsed JSON (W2-12). Arrays show the keys of their first element.

```text
(root): object keys=[config_hash, dependency_graph, files, finished_at, issues, project_root, run_id, started_at, state_delta, summary]
  dependency_graph: object keys=[cycles, edges, mermaid, missing_imports, nodes]
    cycles: array
    edges[]: object keys=[classification, confidence, imported_module, line_number, raw, source_file, status, target_file]
    missing_imports: array
    nodes: array of relative paths
    mermaid: string ("graph TD ...")
  files[]: object keys=[classes, code_map, file_hash, file_path, functions, import_edges, imports, issues, metrics, modified_time, relative_path, size_bytes, syntax_valid]
    code_map: object keys=[classes, docstring_present, functions, imports, module]
    metrics: object keys=[blank_lines, code_lines, comment_lines, documented_symbols, fully_type_hinted_functions, import_count, local_dependency_count, max_cyclomatic_complexity, missing_import_count, total_classes, total_functions, total_lines, total_methods]
    functions[]: object keys=[argument_count, cyclomatic_complexity, decorators, end_line_number, executable_line_count, has_docstring, kind, line_number, missing_type_hints, qualname, return_count, statement_count]
    imports[]: object keys=[bound_names, column_offset, imported_names, kind, level, line_number, module, raw]
  issues[]: object keys=[category, column_offset, details, evidence, file_path, line_number, message, remediation, severity, symbol]
  state_delta: object keys=[deleted_files, modified_files, new_files, unchanged_files]
  summary: object keys=[critical_issues, dependency_cycles, files_scanned, info_issues, minor_issues, missing_imports, production_score, serious_issues, suspicious_short_classes, suspicious_short_functions, syntax_error_files, total_issues]
```

Field semantics:

- **Timestamps.** `started_at`, `finished_at`, and `files[].modified_time` are ISO-8601 UTC with microseconds and a `Z` suffix (`isoformat_utc`, `src/somnus_debug/doctor/core.py:535-539`). [VERIFIED] W2-12 by `od -c` on the file bytes. Lane F's note that the sandbox produced localized timestamps ([fieldkit.md](../_evidence/agent-findings/lane-f-ext/fieldkit.md), "Sandbox caveat") is a display-layer artifact: the bytes on disk are ISO. Lane D reached the same conclusion. [DISCREPANCY] resolved in favor of lane D.
- **`run_id`.** `%Y%m%dT%H%M%SZ` in UTC, one-second resolution (`:82`, `:530-532`). It is present even with `--no-state`.
- **`production_score`** is `max(0, 100 - 20*critical - 8*serious - 2*minor - info)` (`:1772`). Check: 100 - 16 - 10 = 74. [VERIFIED] W2-12.
- **`file_path` in issues** is project-relative, while **`files[].file_path`** is absolute. `files[].relative_path` is the join key.
- **`issues` are duplicated**: the top-level `issues[]` holds everything (sorted by file, line, category), and each `files[].issues` holds that file's subset.
- **`edges[].classification`** takes these values: `local`, `standard_library`, `third_party`, `missing`, `unresolved_relative` (`:1003-1016`). Under `PYTHONPATH=src`, a src-layout project's own `calc.ops` import is classified `third_party`, not `local`. [VERIFIED] W2-14. See [D-22](../DISCOVERY-LEDGER.md#d-22).
- **`state_delta`** compares against the file hashes of the run the `latest` alias points to. With `--no-state` (or no prior run) every file is in `new_files`. [VERIFIED] W2-10 (`new_files` 3), W2-17 (`modified_files: ["src/calc/ops.py"]`).
- **Severity strings** are `critical`, `serious`, `minor`, `info` (`Severity` enum, `:86`).
- **`config_hash`** is the sha256 of the merged raw config. `delta.py` never compares it ([D-21](../DISCOVERY-LEDGER.md#d-21)).

## doctor Markdown report

This section describes the human report.

The report's H2 sections, in order, from the W2-10 report:

1. `Summary`
2. `Issue Categories`
3. `Local State Delta`
4. `Dependency Map` (with `Missing or Unresolved Imports` and `Dependency Cycles`)
5. `Suspiciously Short Classes`
6. `Suspiciously Short Functions`
7. `Full Issue Index`
8. `File Diagnostics` (one H3 per file, with `#### Issue N:` entries)
9. `Recommended Action Plan` (with `### Serious` and `### Minor`)

With the default `markdown_include_css: true`, the report opens with an inline `<style>` block and an HTML "terminal" banner. [VERIFIED] W2-10. With `false` the `<style>` block is omitted; the `<div class="t">` terminal block is still emitted [VERIFIED review-h]. [SOURCE-CONFIRMED] `MarkdownReportWriter`, `src/somnus_debug/doctor/core.py:1776`. The W2-14 run used `false`, but its Markdown was not inspected. [UNVERIFIED] The Markdown is meant for humans. Parse the JSON instead.

## structure output

This section fixes the index format.

```text
# Class Index for `<label>`

Generated by `analyze_python_structure.py` using Python's AST; the source is never imported or executed.

- Class declarations: <n> (<top> top-level, <nested> nested)
- Definitions emitted (module-level functions and class methods): <n>

## class `Name`(Bases) (lines a-b)
**Doc**: <summary>
- `def sig` (lines a-b)
  - <decorators / docstring summary>

## Module-level functions
- `def sig` (lines a-b)
  - <docstring summary>
```

`_No classes found._` replaces the class sections when the file has no classes. Output is deterministic for a given source. [VERIFIED] W2-15 (real output in [command-reference](command-reference.md#structure)); lane D S09-S10.

## pycache-clean output

This section fixes the log format.

Every line is `YYYY-MM-DD HH:MM:SS,mmm [LEVEL] message` on stdout, also appended to `log_file` if one is configured. The stable lines are:

- `Starting pycache cleaner (dry_run=<bool>)`
- `Scanning root: <path>`
- `Summary: deleted <d> directories, <f> files; freed <x> MiB`

The summary says "deleted" in dry-run mode too. [VERIFIED] W2-18.

## delta.py inputs and outputs

This section summarizes the fieldkit regression-gate contract.

- **Inputs.** Two doctor JSON reports. `delta.py` needs only:
  - `issues[].{category, file_path, symbol, message, severity, line_number}`
  - `summary`
  - `files[].relative_path`
  - `project_root`, `run_id`
- **Finding identity.** `(category, file_path, symbol, message)`, with no line number, so code that only moved does not count as new.
- **Dispositions.** `[{"category", "file" (fnmatch), "symbol"? (fnmatch, default "*"), "reason" (required)}]`.
- **`--json` output keys.** `baseline, latest, baseline_run, latest_run, persisting, uncovered_files, deleted_files, added_files, coverage_failure, exit, new, resolved, regressions, dispositioned, stale_dispositions`.

[VERIFIED] W2-17 (`exit 0, persisting 4, coverage_failure False`); lane F [fieldkit.md](../_evidence/agent-findings/lane-f-ext/fieldkit.md) section 3.

## Stability notes

This section states which parts of these contracts are safe to depend on.

- There is no `schema_version` in the doctor JSON. The keys above are what 0.1.0 emits; no compatibility promise exists in code or docs. [SOURCE-CONFIRMED] by absence in `dumps_json(result)` output; the config's `schema_version: "3.0"` describes the config, not the report.
- The first stdout line (`Scan complete: ...`) is the one line the fieldkit itself parses. Treat the other lines as informational.
- The `summary` keys are the most stable surface. `delta.py`, the ratchet recipe, and the W2-21 CI gate all read only `summary` and `issues`.
